# engine — Java/JavaFX quantification engine

> This directory was previously `core_app/`. It is the CLI/GUI quantification & validation engine for LipidXte2. Built as `LipidXte-1.0-SNAPSHOT-jfx.jar`; the Node server invokes it headless under `xvfb`.

## Requirements

- **JDK 8** (the codebase uses JavaFX internals that were removed in later JDKs). Set `JAVA_HOME` to a JDK 8 install before invoking Maven, e.g.
  ```bash
  export JAVA_HOME=/Library/Java/JavaVirtualMachines/zulu-8.jdk/Contents/Home
  ```
- **Maven 3.6+** (Maven 3.8.1+ blocks plain HTTP repos by default; this is fine — `pom.xml` no longer references any HTTP repo and resolves everything from Maven Central).

## Build

```bash
cd engine
mvn -DskipTests package
```

This produces two jars:

| Path | Description |
| --- | --- |
| `target/LipidXte-1.0-SNAPSHOT.jar` | Plain jar (`maven-jar-plugin`). |
| `target/jfx/app/LipidXte-1.0-SNAPSHOT-jfx.jar` | The bundled JavaFX jar — the artifact the Node server runs. |

To deploy a new build, copy the JFX jar into the server directory:

```bash
cp target/jfx/app/LipidXte-1.0-SNAPSHOT-jfx.jar ../server/LipidXte-1.0-SNAPSHOT-jfx.jar
```

The Docker image picks it up from there via `deploy/Dockerfile`'s `COPY server /app`.

## Native bundle (signed JNLP)

The `build-native` execution that signs and bundles a JNLP package is **disabled by default** (`<phase>none</phase>`) because it requires a `pufa.jks` keystore that is not shipped. To enable it, supply a keystore and re-enable the phase:

```bash
mvn -Dpufa.keystore.password=<password> com.zenjava:javafx-maven-plugin:8.8.3:build-native
```

## Run headless (mirrors how the Node server calls it)

```bash
java -jar target/jfx/app/LipidXte-1.0-SNAPSHOT-jfx.jar \
    --op=quant \
    --standard-list=<standard_list.csv> \
    --merged-file=<merged.csv> \
    --output-path=<out_dir> \
    --group1=<g1> --group2=<g2> --group3=<g3> \
    --quant-option=<Quantity|Profile> \
    --output-option=<All|...> \
    [RemoveRef] [SummarizeNCE] [NoCorrection]
```

Use `--op=valid` for the validation/transmission-correction flow.

CLI parsing lives in `src/main/java/de/mpicbg/ms/MainApplication.java`; the orchestrator core is `Pipeline.java`.

## Reference data

The engine reads two on-disk artifacts at runtime:

- `notebooks/polynomials/*.json` — polynomial coefficients for theoretical FA / CO₂-NL intensities. Regenerated by the Jupyter notebooks in [`../notebooks/`](../notebooks).
- `server/LipidXteSqlite.db` — SQLite reference DB (FA anions, etc.) accessed via `org.xerial:sqlite-jdbc`.

When a quant result looks wrong, check whether the polynomial JSON or the notebook that produced it is the source of truth.

## Conventions

- The historical `pufa12` jarsigner password is now a Maven property (`${pufa.keystore.password}`, defaults to `changeme`). Override via `-D` or `~/.m2/settings.xml`.
- Maven plugins are declared in active `<build><plugins>` (not `<pluginManagement>`), so `mvn package` actually triggers the JFX bundling.
