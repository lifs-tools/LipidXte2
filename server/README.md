# server — Node.js orchestrator + bundled engine

> This directory was previously `docker-build/`. It is the production deployment artifact: an Express server that orchestrates the Python preprocessing scripts and the Java engine, bundled with the deployed jar, the reference SQLite DB, and the static web bundle.

The historical `web_app/backend/` was the original source of this server; it was deleted in the public-release refactor to remove the duplicate. `git log --follow server/index.js` walks back into that history.

## What's in here

| Path | Role |
| --- | --- |
| `index.js` | The Express + busboy server. Listens on `:8090` (dev) or `:80`/`:443` (prod). |
| `lipidXte/process.js` | The pipeline orchestrator. Shells out (`child_process.execSync`) to Python and Java. |
| `LipidXte-1.0-SNAPSHOT-jfx.jar` | Deployed JavaFX jar. Rebuild from [`../engine/`](../engine) and copy here. |
| `LipidXteSqlite.db` | Reference DB (FA anions, masses, etc.). Consumed by the Java engine via JDBC. |
| `db.sqlite` | Runtime status DB (batches, tags, file states). Auto-created on first run. |
| `web/` | Static frontend bundle served at `/`. Regenerated by [`../desktop/`](../desktop) `npm run build:web`. |
| `pref/` | Massospec preferences, mounted into the container at `/root/.massSpec`. |
| `package.json`, `yarn.lock`, `pnpm-lock.yaml` | Node manifest + lockfiles. |
| `build.sh` | One-liner that runs `docker build -f deploy/Dockerfile .` from the repo root. |
| `standard_list.csv` | Default standard list, used when a batch upload omits its own. |

## Run locally (without Docker)

```bash
cd server
yarn dev      # cross-env NODE_ENV=development PORT=8090 node index.js
yarn start    # production (reads TLS certs from /app/certs in container or /etc/pki/tls on host)
yarn test     # jest, --testTimeout=10000
npm run lint  # eslint index.js (runs automatically before yarn start)
```

The server expects Python (with [`../preprocessing/`](../preprocessing) deps installed) and a JRE 8 with the deployed jar in scope. Inside Docker both are provided by [`../deploy/Dockerfile`](../deploy/Dockerfile); on bare metal you have to install them yourself.

## Run via Docker (recommended)

From the repo root:

```bash
cd deploy
docker compose up --watch
```

`develop.watch` syncs `../server/lipidXte` into the container live.

## Pipeline

`/process` (GET, with custom headers `timestamp`, `title`, `classname`, `group1..3`, `quantoption`, `outputoption`, `options`) triggers the four-step pipeline in `lipidXte/process.js`:

1. `python3 src/peakStrainer.py <folder>` (cwd: `/app/preprocessing`) — RAW → mzXML, only if RAW files present.
2. `python3 src/reorder.py <folder>` — reorder, only if step 1 ran.
3. `python3 src/lipidXplorer2Lipidx.py <className> <folder>` — produces `merged.csv` (skipped if already present).
4. `java -jar LipidXte-1.0-SNAPSHOT-jfx.jar --op=quant ...` (cwd: `/app`) — Java engine, headless under `xvfb`.

Status of each batch is tracked in `db.sqlite`:

```sql
CREATE TABLE Batches (ID INTEGER PRIMARY KEY, Batch TEXT, Title TEXT, Status TEXT);
CREATE TABLE Tags (ID INTEGER PRIMARY KEY, Tag TEXT UNIQUE);
CREATE TABLE Batches_Tags (BatchID INTEGER, TagID INTEGER, UNIQUE(BatchID, TagID));
CREATE TABLE BatchesFiles (BatchID INTEGER, FilePath TEXT, Status TEXT, UNIQUE(BatchID, FilePath));
```

## TLS certificates

`index.js` reads:

- `/app/certs/lipidxte.{key,pem}` when running in the Docker container (mounted from the host).
- `/etc/pki/tls/private/lipidxte.key.<year>` and `/etc/pki/tls/certs/lipidxte.pem.<year>` when running on bare metal in production mode.

Update the paths in `index.js` (around line 925) on cert rotation. **Never commit cert material**: the top-level `.gitignore` blocks `*.key` / `*.pem` and the `certs/` directories.

## Rebuilding the deployed jar

```bash
cd ../engine
export JAVA_HOME=/path/to/jdk8
mvn -DskipTests package
cp target/jfx/app/LipidXte-1.0-SNAPSHOT-jfx.jar ../server/LipidXte-1.0-SNAPSHOT-jfx.jar
```

The Docker image does NOT run Maven — it copies the jar from `server/` at build time.
